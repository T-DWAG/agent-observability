专题 4

Eval 生产化（异步评估）

同步 LLM-as-Judge → 异步执行 · 原子防重 · 状态追踪 · 超时重试。HTTP 不再卡等 LLM。

1
现状 vs 目标
❌ 同步（当前）
POST /evaluations
↓ 阻塞 5~30s
llm.Complete() — 可能超时
↓
200 OK（或 504 超时）

网关超时断开 → 用户不知道评了没

✅ 异步（目标）
POST /evaluations
↓ 原子创建唯一 overall；重复则 409
↓ 毫秒级
202 Accepted
↓ 后台
llm.Complete(timeout, retry×3)
↓
done / failed

GET 轮询 overall 状态 · items 只含三维评分

2
评估状态机
pending
→
running
→
done
|
↘
failed
状态含义触发条件
pending已提交，等待执行POST 202 返回后
runningLLM 调用中后台 goroutine 启动后
done评分成功落库3 条维度评分全部 Save
failed评估失败LLM / JSON / 任一维度保存失败
3
改动清单
文件变更说明
model/evaluation.go字段+唯一索引Status + ErrorMsg；trace_id/dimension 唯一
model/constants.go+4 常量EvalStatusPending/Running/Done/Failed
evaluation/llm.go+RetryCompleter超时 + 指数退避重试
evaluation/judge.go重构Evaluate → EvaluateAsync + runEvaluation
storage/interface.go+原子方法CreateEvaluationJob + UpdateEvaluationStatus
storage/memory.go+实现锁内防重；状态只更新 overall
storage/postgres.go+实现ON CONFLICT 防重；状态只更新 overall
api/eval.go重写202 / 重复 409 / 顶层状态
cmd/server/main.go可选RetryCompleter + OBS_JUDGE_* 环境变量
4
API 变化
方法路径旧行为新行为
POST/api/v1/evaluations200 + 完整评分首次 202；同一 trace 重复提交 409
GET/api/v1/evaluations/{trace_id}评分列表顶层 status/error_msg + 三维 items
轮询示例
POST /api/v1/evaluations {"trace_id":"abc"} → 202
GET /api/v1/evaluations/abc → {"status":"running","error_msg":"","items":[]}
几秒后再 GET → {"status":"done","items":[3条维度评分]}
