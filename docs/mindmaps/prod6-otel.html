Production Topic 06

OTel 适配导出

内部继续使用 obs_* 作为事实源，新增一个只读翻译层，把一条已有 Trace 映射为 OTLP/HTTP，送到 Jaeger、Tempo、SigNoz 或其他兼容 Collector。

01专题主链路

API Key → tenant
→
GetTrace + GetTraceSpans
→
Mapper
→
OTLP protobuf
→
外部 Collector / APM

02不变的内部事实源

已有主路径

Eino Callback → Collector → Storage → obs_traces / obs_spans。专题 6 不改这条链路。

新增适配路径

显式导出一条 Trace。只读内部数据，导出成功或失败都不回写 Storage。

03为什么不重写成 OTel 内部模型

  • 当前表已经承载租户、采样、TTL、Eval、Metrics 语义。
  • Eino 回调采集仍是本项目的教学主线。
  • OTel 是对外契约，适配层集中处理字段演进。
  • 避免为了换 UI 推倒已完成的存储和 API。

04字段与关系映射

TraceID
内部 UUID / 历史字符串 → 稳定 16 字节 OTel TraceID；同一 Trace 的所有 Span 一致。
SpanID
内部 SpanID → 稳定 8 字节 OTel SpanID；不使用导出时随机值。
ParentSpanID
空值表示根 Span；非空值原样映射父子关系。
时间
StartTime / EndTime → OTel 生命周期时间，不用导出时刻覆盖业务时间。
业务字段
SpanType、ModelName、Token、Cost、ToolName → OTel/GenAI 与 obs.* 属性。
正文
默认不导出；只有 OBS_OTEL_EXPORT_CONTENT=true 才允许加入 content 属性。

05租户边界

先调用 GetTrace(tenant, traceID)，再读取 Span。A 租户访问 B 的 Trace 得到 404，不能先查全库再判断。

06第一版出口

POST /api/v1/traces/{id}/export。同步导出一条 Trace，Collector 不可用返回 502，未配置返回 503。

07后置能力

自动双写、批量回灌、队列重试、死信、分布式幂等和 Trace UI 不在第一版。
