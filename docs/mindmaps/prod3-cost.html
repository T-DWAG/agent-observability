实践篇 · 专题 3

采样 · 保留 · 成本

生产收紧：成功抽样 · TTL 清理 · 单价可配 · 尖刺打日志

1 三道闸
闸问题本专题落地
采样这条还存吗？shouldKeep + PurgeTrace
保留存多久？PurgeBefore + OBS_RETENTION_DAYS
成本花多少？谁贵？单价表 + CostAlert 日志
2 采样管道 
finishTrace
  status / TotalCost 已齐
  → shouldKeep?
       error / cost≥阈值 → 必留 → SaveTrace
       success → SampleSuccessRate 掷骰
       不留 → SampledOut++ → PurgeTrace
3 设计理由
为何尾部判定？要先知道成败与费用，才能「错全留、贵全留」。
为何要 Purge？Span 执行中已写入；只丢 Trace 会留孤儿行。
rate<0 当全留？兼容旧 Config{}；显式 0 才测「成功全丢」。
告警为何只打 log？先证明闸门；webhook 后置。
4 验收
动作期望
error + rate=0仍落库
success + rate=0无 Trace；SampledOut≥1
cost≥CostKeep必留
PurgeBefore旧数据删除
SetPriceTableEstimateCost 变化
